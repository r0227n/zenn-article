## セッション＆コンテキスト管理

### DeepWiki MCP の活用

**[DeepWiki MCP](https://docs.devin.ai/work-with-devin/deepwiki-mcp) はマジで便利です。**

OSS関連の実装が絡む場合、ServiceやRepository実装時に積極的に使うことをおすすめします。

[Context7](https://github.com/upstash/context7)はドキュメント参照のみのため、使い方を`Claude`が推測する必要があり、セッションが汚れてハルシネーションが発生しやすくなります。
一方、[DeepWiki MCP](https://docs.devin.ai/work-with-devin/deepwiki-mcp) を使うことで、セッション内の情報が以下のように整理されます。

> **Q.** このOSSどう使えばいい？
> **A.** （MCP経由で）こう使う

Private Repositoryについても、[Devin MCP](https://docs.devin.ai/work-with-devin/devin-mcp)があるため問題なく対応できます。

### AskUserQuestion の積極的な活用

`Claude Code`が自走する際、ユーザーに判断を伺うようになるため、**AskUserQuestionは積極的に使いましょう。**

これにより、AIが暴走せず、適切なタイミングで人間の判断を仰ぐことができます。

### PlanMode で作業を開始する

プロンプトに対して必要な情報を集めてからplan（ファイルに情報を一旦書き出し）し、ユーザーが判断できるようにします。

`agent-Explore`がメインですが、作業前の前提条件を確認することで、期待する成果物に近づけることができます。

### Subagentsの整備

**Subagentsの整備は非常に重要です。**

![](https://storage.googleapis.com/zenn-user-upload/b8b0d59e0e89-20260105.png)

`Subagents`は別セッションで情報を取得し、その情報をメインセッションに持ってきてくれます。これにより、メインセッションは必要な情報を効率よく取得できます。

具体的な運用としては、以下を組み合わせます。

- `Subagents`
- `/compact`
- `AskUserQuestion`

`Claude`が自走を開始する前に、処理に必要な情報を調査させます。`PlanMode`で実行しているため、自走前に情報の精査を人間が行え、生成結果をコントロールできます。

## プロンプト設計

### 曖昧な指示を避ける

**曖昧な指示は避けましょう。**

目的が同じでも、「多言語化対応」という自由に解釈できる用語を使うのではなく、明確に「〇〇を使って××をする」と指示すると、期待通りの出力が得られやすくなります。

:::details 参考例

| プロンプト | 結果 |
| --- | --- |
| [多言語化対応してください](https://github.com/r0227n/WhisperPad/pull/86) | 曖昧で解釈にブレが生じる |
| [String Catalog（Swiftの多言語化対応方法）対応してください](https://github.com/r0227n/WhisperPad/pull/95) | 具体的で期待通りの実装 |

:::

### 用語集をリポジトリに追加する

プロジェクト固有の用語集をリポジトリに追加することで、造語にも対応可能になります。

```
<造語>に対して、〇〇をしてください
```

というプロンプトに対しても、`Claude`は`<造語>`を認識できるようになります。これにより、コミュニケーションコストが大幅に下がります。

### 「なぜ？なぜ？」プロンプト

:::message
[feature-dev plugin](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/feature-dev) の「言語化ができていないタスク」に対するプロンプト版です。
:::

**「明確なプロンプト = 生成結果のクオリティ」** ですが、言語化できない事柄は多いものです。

そのため、以下のような問答を繰り返します。

1. 👤「`<わからないこと>`を教えて？」
2. 🤖「〇〇です」
3. 👤「〇〇を教えて？」
4. 🤖「××です」
5. 👤 が理解するまで1〜4を繰り返す
6. `/compact <理解した内容>`
7. `<理解した内容>を実行して`

:::message alert
**この時、`/clear`は実行しないのがポイントです。**

`/compact`はしますが、セッション内の情報は資産です。AIが生成時に参照しますし、人間がレビューする際に意図を汲みやすくなります。絶対に情報を残しましょう。
:::

## 開発環境の運用

以下の整備は非常に重要です。

- linter

- Git hooks

今回は0→1で開発していましたが、最初のうちは整合性が合わない出力が多くありました。しかし、**体感で3割ほど作り切った後は、整合性のある出力が増え始めました。**

そのため、テンプレートリポジトリを用意することで

### GitHub Copilot の活用

![](https://storage.googleapis.com/zenn-user-upload/911dcda0c161-20260105.png)

テンプレートプロジェクトの話にも関連しますが、**Jumpstart your project with Copilot (optional)** が便利なので使っていきましょう！
これはリポジトリ作成時にプロンプト(500文字以内)を入力し、Agentがプロンプトに応じた内容を自動実行してくれる機能です。
今回はTSで便利ツールを作りたいと思い、簡易的な仕様書をプロンプトとして入力しました。
(便利ツールの内容が倫理的に公開するのは、、、っと思っているのでPRのスクショとなります。)


![](https://storage.googleapis.com/zenn-user-upload/216283ff4983-20260105.png)

今回はテンプレートなしでプロジェクトを作成しましたが、Copilotが仕様通りに動くコードを作ってくれました。
「リポジトリ作成＆ちょっとした便利ツールの雛形」が『リポジトリの作成』だけで完了しまます！

### セッション情報を活用した設定更新

`.claude`のファイルは基本的に以下のフローで作成しています。

1. `Claude Code`にタスクを実行してもらう
2. `/compact`で1を圧縮
3. 「2を説明し、`.claude`にfeatureを追加して」+ 「不明点はAskUserQuestionでユーザーに確認して」+ `ultrathink`

基本的に生成AIにはガチャ要素があります。そのため、`.claude`のサブディレクトリは**AIツールに対してガチャ要素を限りなく抑えるための再現性ファイルの集合体**という認識です。

| ディレクトリ | 役割 |
| --- | --- |
| `agents` | Claudeが情報を取得するフロー |
| `commands` | ユーザーがAIに対して指示する定型処理 |
| `skills` | Claudeが情報を精査するフロー |
| `rules` | Claudeが処理するフロー |

### マルチリポジトリ開発

`開発リポジトリ`と`plugin専用リポジトリ``を`--add-dir`（Claudeがアクセス可能にする）することで、**プロジェクト固有と汎用的なワークフローを同時に作成できます。**

![](https://storage.googleapis.com/zenn-user-upload/793bf201b4ec-20260105.png)

※ 開発リポジトリで得たセッション情報を元に`.claude`ディレクトリに出力させたら、`plugin専用リポジトリ`側にも出力された時のログ

これにより、

- プロダクト専用の`.claude`の育成
- 汎用的な`pluguin`の育成

をすることにより、中長期目線で高速化を狙うことができます。

## 所感

### CLAUDE.md の役割

`CLAUDE.md`はコンパイラ的な立ち位置とし、以下の内容だけで良いような気がします。

- `docs`と`.claude`ディレクトリの紐付け
- [gtr](https://github.com/coderabbitai/git-worktree-runner)のようなドキュメントに書き出すほどではないが、`Claude`にも理解して欲しいツール情報

役割分担としては：

| ディレクトリ | 対象 | 目的 |
| --- | --- | --- |
| `docs` | 人間 | 人間が理解できるようにドキュメントを整備 |
| `.claude` | AI | Claudeの入出力フォーマットを整備 |

### 並列開発について

エージェントもSubagentsを並列稼働させて情報を処理しています。そのため、開発も実装単位でworktreeを分けて実装し、**メインセッションは「実装worktreeの管理のみ」という運用が理想**だと感じました。

[gtr](https://github.com/coderabbitai/git-worktree-runner)は便利ですし、タスクの粒度を小さくしていたので、並列開発＆レビューもコストは低かったです。ただし、CursorのUIはごちゃごちゃ感があり、並列開発時にノイズが多いため、Vimmerになるとストレスが低いかもしれません。

## まとめ

ハッカソンを通じて、`Claude Code`を効果的に運用するためのポイントを学びました。

- **セッション管理**: [DeepWiki MCP](https://docs.devin.ai/work-with-devin/deepwiki-mcp)や`Subagents`を活用し、クリーンなコンテキストを維持する
- **プロンプト設計**: 曖昧さを排除し、用語集やなぜ？なぜ？プロンプトで精度を上げる
- **開発環境**: リンター・フォーマッター・テンプレートを整備し、再現性を確保する

生成AIはガチャ要素がありますが、適切な環境とプロセスを整えることで、そのブレを最小限に抑えられます。ぜひ参考にしてみてください。
